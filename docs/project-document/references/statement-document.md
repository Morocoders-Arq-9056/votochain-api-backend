## Objetivo

El presente documento define el trabajo final y la rúbrica que permite evaluar el logro del curso 1ASI0728 Arquitecturas de Software Emergentes.

## Logro del curso

Al finalizar el curso, el estudiante comunica resultados y proceso de ingeniería aplicado para el ciclo de desarrollo y despliegue de una solución basada en tecnologías emergentes, distribuida bajo una arquitectura de soluciones multicomponente con tecnologías diversas, que satisface requisitos para empresas o público en general, con un enfoque innovador e inclusivo, en un ambiente ágil y colaborativo, desplegada sobre plataformas Server Side, Cloud y Web3, haciendo uso de tecnologías open-source para los distintos niveles de los componentes para la solución.

En Ingeniería de Software, el logro contribuye a alcanzar la **COMPETENCIA ABET 3 – TRABAJO MULTIDISCIPLINARIO** - Capacidad de comunicarse efectivamente con un rango de audiencias.

## Enunciado

El curso de Arquitecturas de Software Emergentes tiene una naturaleza teórico-práctica, por lo que es necesario evidenciar la capacidad para llevar a cabo procesos de Ingeniería de Software con el fin de obtener una solución de software compuesta por un conjunto de productos digitales, con la implementación de una arquitectura de aplicación empresarial basadas en tecnologías clave o emergentes para la transformación digital, bajo una aproximación de domain-driven design. La solución de software debe estar orientada a satisfacer necesidades identificadas para un público objetivo, considerando el impacto de esta en el contexto global, económico, ambiental y social en el cual operaría, haciendo uso de las herramientas y tecnología utilizadas en el curso, aplicando conceptos, técnicas, patrones, arquitecturas y buenas prácticas revisados en clase ó resultado de la investigación. Dentro del alcance de la solución debe evidenciarse la aplicación de principios y patrones de diseño a nivel arquitectónico y de detalle, cuyas características sean utilizadas por los productos que formen parte de la solución de software.

Por otro lado, la arquitectura de la solución debe estar conformada por un conjunto de productos digitales basados en tecnologías relacionadas con transformación digital, incluyendo RESTful APIs de elaboración interna, Web Applications, Native Mobile Applications, entre otros, con la adecuada integración entre los productos de la solución. Se incluye como parte del alcance el Landing Page del modelo de negocio. Como parte de las características a considerar, además de la integración entre los productos de elaboración interno, debe acceder a algún servicio externo de terceros. Es importante recalcar que desde la perspectiva de experiencia de usuario, ésta debe ser consistente entre el Landing Page y las aplicaciones Web, native Mobile u otro tipo de productos digitales con los que interactúe el usuario. Los call-to-action para cada segmento objetivo del Landing Page deben redirigir al usuario a las vistas correspondientes en las Web Applications o a los sitios de descarga de las aplicaciones móviles o a un punto de acceso adecuado según la naturaleza del producto digital referenciado.

| Nivel | Descripción |

| 3 | Problema mayor: ocurre frecuentemente o los usuarios no son capaces de resolverlos. Es importante que sean corregidos y se les debe asignar una prioridad alta. |

**DESCRIPCIÓN DE PROBLEMAS:**

**PROBLEMA #1:** No hay un control que permita regresar a la tienda durante el trámite de compra

- **Severidad:** 3
- **Heurística violada:** Usabilidad - Libertad y control del usuario

**Problema:**

Una vez el cliente pase al trámite de compra, en caso de que este quiera regresar a la tienda, no hay un botón que lo envíe al inicio de la web, lo cual nos obliga a efectuar el trámite y al momento de elegir más productos, realizar otro, incrementándose así la cantidad de esfuerzo del usuario.
